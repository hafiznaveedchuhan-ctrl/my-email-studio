The guardrail, live

Watch it block a mistake

The send-guard runs before any send. A real address? Blocked. A broadcast? Blocked. Only the test inbox gets through.

send-guard.mjs — PreToolUse hook
# try to email a real-looking lead
❯ echo '{"tool_name":"send_email","to":["ava@example.com"]}' | node send-guard.mjs
[send-guard] BLOCKED: recipient "ava@example.com" is not allowed · exit 2
# try a broadcast
❯ echo '{"tool_name":"send_broadcast", ...}' | node send-guard.mjs
[send-guard] BLOCKED: broadcast-style tool is never allowed · exit 2
# the only thing it lets through
❯ echo '{"tool_name":"send_email","to":["delivered@resend.dev"]}' | node send-guard.mjs
✓ allowed · delivered to localhost:4000 practice server · exit 0

Why it's safe

Three independent layers

One mistake isn't enough to email a real person — each layer catches what the others might miss.

01

Golden rules

Practice server only, allow-listed recipients, no broadcasts, no secrets in git, fake data only.

02

Send-guard hook

Runs before any send and blocks broadcasts, unknown recipients, and sends with no recipient.

03

No real credentials

The owner email lives only in a gitignored file; the MCP config uses a dummy key and localhost.

Agent wants to send→ 🛡️ send-guard→ ❌ broadcast / bad / empty→ ✅ @resend.dev · localhost:4000
